# 公开资料、权限与安全边界

> 这个仓库是**公开**的。任何内容都可能被合作组外的人看到。  
> 本章规定：什么可以放进来，什么绝对不能放。

---

## 1. 可以放的内容

- 公开论文、公开预印本（带 DOI/arXiv 链接）；
- 公开的 basf2 / Belle II 软件文档链接；
- 官方公开 tutorial 的链接和摘要；
- 本项目自己写的文字、代码、图；
- 自己推导的公式（不包含内部未公开数据）；
- 公开的 PDG 数值；
- 自己的 cutflow（**不含内部数据内容**）。

---

## 2. 不能放的内容

- ❌ Belle II 内部未公开的 ntuple、ROOT 文件、数据样本；
- ❌ 内部会议材料、未公开的 performance 图；
- ❌ 其他分析者的私有 GitLab/GitHub 代码；
- ❌ 内部分析笔记的原文（除非作者明确授权，且仓库是私有的）；
- ❌ 任何 token、密码、cookie、proxy 凭据；
- ❌ 别人的 personal access token；
- ❌ 未经授权的合作组内部文档截图；
- ❌ 受版权保护的 PDF（除非是开放获取/有许可）。

> 如果要用内部资料，请在**私有仓库/私有环境**中使用，并记录授权人和范围；不要把内容复制到本公开仓库。

---

## 3. Token 安全

### 3.1 绝对不要

- 把 GitHub/GitLab token 写进 README、代码、issue、聊天；
- 把 token 放在 URL 里：

  ```text
  https://<token>@github.com/...
  ```

- 把 token 截图发群；
- 让 AI 使用别人的 token 推送。

### 3.2 如果 token 已经泄露

1. 立刻去 GitHub/GitLab **Revoke**；
2. 检查最近的操作记录；
3. 重新生成 token；
4. 用 SSH key 或 credential manager，不要把 token 写进文件。

### 3.3 本仓库的规则

- 本仓库不保存任何 token；
- 代码里不出现 `ghp_`、`glpat-` 等字符串；
- 如果发现，立刻删除并 revoke。

---

## 4. AI / Agent 的权限

允许：

- 读取本仓库的公开文件；
- 读取公开的 basf2 文档；
- 读取公开的论文/预印本；
- 生成代码和文档；
- 在本地运行测试。

不允许：

- 读取私人 GitLab/GitHub 仓库；
- 使用别人的 token；
- 把内部数据上传到公开仓库；
- 把内部文档内容复制到公开文档；
- 未经授权抓取合作组内部页面。

> 如果任务需要内部资料，应该：
> 1. 由项目负责人明确授权；
> 2. 在私有环境/私有仓库进行；
> 3. 公开仓库只保留“方法”和“公开入口”，不保留内部内容。

---

## 5. 引用与许可

- 论文：引用 DOI/arXiv；
- 软件：引用 basf2 官方文档/论文；
- 代码：如果参考了公开示例，注明来源和 license；
- 图：自己画的，或使用有许可的公开图；
- 不要把别人的图直接截图放进公开仓库而不注明来源。

---

## 6. 提交前检查

- [ ] 没有 token/密码/cookie；
- [ ] 没有内部数据/ntuple；
- [ ] 没有他人私有代码；
- [ ] 没有未公开的会议材料；
- [ ] 所有引用有链接；
- [ ] 所有图有来源；
- [ ] 公开库内容可以给合作组外的人看。

---

**公开库只放“公开资料 + 自己写的东西”。内部资料留在内部，token 永远不进仓库。**
